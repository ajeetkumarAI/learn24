02Questions and model answers

Q1
What is the difference between ROW_NUMBER() and ROWID in Oracle?
  • ROWID: a physical address pseudocolumn identifying where a row is stored (data object, file, block, slot). It is fast for direct access, unique per row in a table, but can change after operations such as table moves or export/import. Not for business logic.
  • ROW_NUMBER(): an analytic function that assigns a sequential number to rows in a result set based on OVER (PARTITION BY ... ORDER BY ...). Used for ranking, top-N per group and deduplication.
  • Also: ROWNUM is a pseudocolumn assigned before ORDER BY, a classic pitfall for top-N queries.
Q2
Find the third-highest salary.
SELECT DISTINCT salary
FROM (SELECT salary, DENSE_RANK() OVER (ORDER BY salary DESC) AS rk FROM employees) t
WHERE rk = 3;
-- alternative: SELECT salary FROM employees ORDER BY salary DESC OFFSET 2 ROWS FETCH NEXT 1 ROW ONLY;  (ties differ!)
  • Explain the difference with ties: DENSE_RANK gives the third distinct salary; OFFSET gives the third row.
Q3
Use a CTE + window function to compute each customer's running balance.
WITH tx AS (
  SELECT customer_id, txn_date,
         CASE WHEN type = 'CREDIT' THEN amount ELSE -amount END AS signed_amt
  FROM transactions
)
SELECT customer_id, txn_date, signed_amt,
       SUM(signed_amt) OVER (PARTITION BY customer_id ORDER BY txn_date
                             ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS running_balance
FROM tx;
Q4
How do you optimise a slow SQL query in a bank's reporting system?
  • Read the execution plan: full scans, bad join orders, sorts spilling to disk.
  • Indexes on the join and filter columns (composite, in the right column order); avoid functions on indexed columns in WHERE.
  • Reduce data early: filter before joining, select only the needed columns, pre-aggregate.
  • Partition large fact tables by date; use materialised views for repeated reports; update statistics.
  • Measure before and after, and keep correctness checks (row counts, totals).
Q5
Dijkstra's shortest path: implement it in Python.
import heapq
def dijkstra(graph, src):                 # graph: {u: [(v, w), ...]}
    dist = {src: 0}; pq = [(0, src)]
    while pq:
        d, u = heapq.heappop(pq)
        if d > dist.get(u, float("inf")): continue
        for v, w in graph.get(u, []):
            nd = d + w
            if nd < dist.get(v, float("inf")):
                dist[v] = nd; heapq.heappush(pq, (nd, v))
    return dist
  • O((V + E) log V) with a binary heap; it needs non-negative weights (otherwise use Bellman-Ford).
