Project 7: Support Ticket Triage & Reply Copilot

🛠️ Beginner⏱ 1–2 weekends📄 Resume lines included

A business-friendly project combining classical NLP + LLMs: classify incoming tickets by intent, urgency and sentiment, route them, and draft grounded replies from a knowledge base for an agent to approve.

What you'll build

  • A classifier: intent (billing / delivery / refund / technical / other), priority and sentiment.
  • Routing rules and SLA timers per queue.
  • A reply copilot: RAG over FAQ and policy articles drafts a reply with citations; the agent edits and approves.
  • A dashboard: volume by intent, misroutes, time saved.

Architecture

Ticket → PII masking → fast classifier (TF-IDF + LogReg or DistilBERT) → confidence?
     high → route to queue          low → LLM zero-shot classification fallback
     → RAG(KB) → draft reply (JSON: reply, citations, needs_human: bool) → agent review UI → send
Feedback (edits, reroutes) → retraining data

Tech stack

scikit-learn or Hugging Face Transformers, an LLM, FAISS, FastAPI, Streamlit, plus a public dataset (e.g. customer-support ticket datasets on Kaggle or Hugging Face).

Step by step

  1. Dataset: load tickets with intent labels; split by time if timestamps exist.
  2. Baseline: TF-IDF + logistic regression; report macro-F1 per intent.
  3. Upgrade: fine-tune DistilBERT; compare accuracy and latency.
  4. Fallback: use LLM zero-shot classification when the classifier's confidence is below 0.6.
  5. PII masking (emails, phones, card numbers) before any LLM call.
  6. Reply drafting: RAG over the KB, with a structured JSON output that includes needs_human.
  7. Agent UI: show the draft, the citations and an edit box; log the edit distance as a quality signal.
  8. Measure: macro-F1, the share of drafts sent with minor edits, and average handling time saved.
