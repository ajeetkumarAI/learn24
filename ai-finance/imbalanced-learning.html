Imbalanced Learning & Cost-Sensitive Evaluation

⏱ 10 min read✅ Check-yourself quiz🏦 Banking & fintech

In fraud, default and AML problems the positive class is rare, often well under 1%. Models trained naively learn to predict "not fraud" and look great on accuracy. This lesson covers the techniques that actually work.

Pick the right metrics first

  • PR-AUC (average precision): focuses on the rare class. Prefer it to ROC-AUC under heavy imbalance.
  • Recall at a fixed precision (or at a fixed alert rate): matches how operations teams work.
  • Cost-weighted metrics: expected loss = FN × fraud cost + FP × review/friction cost.
  • Calibration: if a probability feeds a pricing or limit decision, check reliability curves or the Brier score.

Data-level techniques

Technique Idea Watch out for
Random undersampling Drop majority rows Loses information; re-weight or calibrate afterwards
Oversampling / SMOTE Duplicate or synthesise minority rows Apply only inside the training folds; can create unrealistic points
Time-aware sampling Keep the temporal order Required for out-of-time validation

Algorithm-level techniques

  • Class weights: class_weight="balanced" (scikit-learn) or scale_pos_weight ≈ negatives / positives (XGBoost, LightGBM).
  • Focal loss: down-weights easy negatives in neural networks.
  • Anomaly detection: Isolation Forest or autoencoders when labels are very scarce. Use them as features or as a first filter.
  • Ensembles of balanced subsets (EasyEnsemble, BalancedRandomForest).

Undersampling changes probabilities: correct them

If you keep only a fraction β of the negatives, the model's predicted probability p_s is inflated. The corrected probability is:

[ p = \frac{\beta\, p_s}{\beta\, p_s - p_s + 1} ]

Or simply recalibrate on untouched validation data with Platt scaling or isotonic regression.

Choose the threshold by cost

import numpy as np
def best_threshold(y, p, cost_fn=5000, cost_fp=50):
    ts = np.linspace(0.01, 0.99, 99)
    costs = [((p < t) & (y == 1)).sum() * cost_fn + ((p >= t) & (y == 0)).sum() * cost_fp for t in ts]
    return ts[int(np.argmin(costs))]
  • Add operational constraints, for example "at most 2,000 alerts a day", and pick the best threshold that satisfies them.

Validation design

  • Use out-of-time validation (train Jan–Sep, validate Oct–Dec).
  • Use grouped splits by customer, so the same customer never appears in both train and test.
  • Report the metrics with confidence intervals; rare positives make estimates noisy.

Check yourself

Where should SMOTE be applied in cross-validation? Only to the training portion of each fold, inside a pipeline. Applying it before splitting leaks synthetic copies of validation points into training.
Your model was trained on 10% of the negatives. Can you use its probabilities directly for loss estimates? No. They are inflated. Apply the prior-correction formula or recalibrate on a representative, untouched validation set.
Why can ROC-AUC look excellent while the model is useless operationally? ROC-AUC counts true negatives, which are abundant. A model can rank well overall but still produce far too many false positives at the thresholds operations can afford. PR curves expose this.
