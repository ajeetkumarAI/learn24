Which AI Framework Should You Use?

⏱ 10 min read🎯 All levels🖼 2 diagrams🧪 1 live demo

There are now many frameworks for LLM apps and agents, and they overlap. The good news: the core ideas (prompts, tools, retrieval, loops, memory, tracing) are the same everywhere. Learn them once with LangChain and LangGraph, and you can pick up any other framework in a day. Here is how they compare, and how to choose.

01The same building blocks everywhere

Learn concepts, not just APIs. Framework APIs change every few months; the ideas in GenAI Course Modules 8–9 and these notes do not.

03Choose with your requirements

Demo · What are you building?
Question to askWhy it matters
Do I need loops or approvals?if not, a chain or plain SDK call is enough
Which models must I support?single-vendor SDKs lock you to one provider
How will I debug it?tracing (LangSmith, provider dashboards, OpenTelemetry) is essential for agents
Who maintains it?large, active projects get security fixes and new model support quickly
Can I test it?explicit workflows are much easier to unit-test than free-roaming agents

04When to use no framework

Frameworks save time, but every layer adds something to learn and debug. Use plain provider SDKs when the app is a single call, a short fixed chain, or performance-critical. Many production teams start with the SDK, then adopt LangGraph when they need checkpoints and approvals.

05Summary

  • All frameworks share the same blocks: model, tools, knowledge, control flow, memory + tracing.
  • LangChain for parts and simple agents, LangGraph for controlled workflows, LlamaIndex for data-heavy RAG.
  • CrewAI for quick multi-agent prototypes; Microsoft Agent Framework for Azure/.NET; OpenAI Agents SDK, Google ADK and Claude Agent SDK for their ecosystems.
  • For one simple call, skip the framework.
