Cloud Service & Deployment Models

⏱ 12 min read🎯 Beginner friendly🖼 3 diagrams🧪 2 live demos

“Cloud” is not one thing. There are three service models (how much the provider manages for you) and three deployment models (where the cloud lives and who can use it). Get these six words right and half of every cloud interview is done.

03Public, private and hybrid cloud

ModelWhat it isGood forExample
Public cloudprovider’s hardware, shared by many customers (tenants), over the internetlow cost, no hardware, unlimited scalea blog or website on AWS EC2
Private cloudcloud setup used by one organisation only (own data centre or hosted)strict security, compliance, full controla bank’s internal core-banking platform
Hybrid cloudprivate + public, connected securely (VPN or AWS Direct Connect)keep sensitive data inside, use the cloud for the restbank keeps balances on-premises, runs its mobile app front end on AWS
🚗

Like transport. Public cloud = taking a cab (shared, pay per ride). Private cloud = owning a car (yours alone, you maintain it). Hybrid = your own car for daily use plus cabs for long trips.

Note: “Shared” in a public cloud does not mean others can see your data. Each customer is isolated by virtualisation and security controls (you will see how in Day 4).

04What happens when you deploy a web server

🎯 Exam corner
  • IaaS = most control (EC2). PaaS = deploy code only (Elastic Beanstalk). SaaS = ready software.
  • Hybrid cloud questions usually mention connecting on-premises with AWS: VPN or Direct Connect.

05Summary

  • IaaS: you manage OS and apps (EC2). PaaS: you manage only code and data (Elastic Beanstalk). SaaS: ready software (Gmail).
  • Public = shared provider hardware; private = one organisation; hybrid = both, connected securely.
  • Deploying a website: launch EC2 → open port 80 → install a web server → add index.html → visit the public IP.
