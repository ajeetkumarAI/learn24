SSH is a secure phone line into the server. Instead of a desktop (RDP), you get a text window where you type commands.

Note: every Linux system has a root user, but on EC2 you never log in as root directly. You log in as ec2-user/ubuntu and use sudo (Day 11).

04Fixing common SSH errors

Demo · What does the error mean?
  • Port 22 open to the world is attacked by bots all day. Restrict it to My IP.
  • Best practice in companies: Systems Manager Session Manager (no port 22, no key pair, no public IP, every session logged) or EC2 Instance Connect Endpoint for private subnets.
  • Never share .pem files in chat or email, and never commit them to Git.
🎯 Exam corner
  • Linux → SSH, port 22, key pair.
  • No SSH keys, no bastion, audited sessions → Session Manager.
  • Reach an instance in a private subnet without a public IP → Session Manager or EC2 Instance Connect Endpoint.

05Summary

  • Linux EC2: SSH, port 22, user ec2-user or ubuntu, private key instead of a password.
  • Connect from the browser, CMD/PowerShell, a Linux/Mac terminal, MobaXterm (.pem) or PuTTY (.ppk).
  • ssh -i key.pem user@public-ip; protect the key with chmod 400.
  • Timeouts = security group; “publickey” = wrong user or key.
  • Production: Session Manager instead of open port 22.
