01The transformer, end to end

The original transformer (2017) was built for translation. It has two halves: an encoder that reads and understands the input sentence, and a decoder that writes the output sentence one token at a time, while looking back at what the encoder understood.

PartWhat it doesOriginal size
Embeddingturns each token into a vectord_model = 512
Encoderself-attention + feed-forward, repeated6 layers
Decodermasked self-attention + cross-attention + feed-forward6 layers
Output headlinear layer + softmax over the vocabulary~37,000 tokens (shared vocab)
🗣️

Like a human interpreter. First they listen to the full sentence and understand it (encoder). Then they speak in the other language word by word, glancing at their understanding each time (decoder).

02Why word order has to be injected

Here is the surprise. Self-attention compares every word with every other word, but the calculation does not care where a word sits. If you shuffle the words, each word gets exactly the same attention scores, just in a different row.

So the transformer must be told the position of each token. We do this by adding a positional encoding vector to each token embedding before the first layer:

input to layer 1 = token embedding + positional encoding

RNNs never needed this, because they read words one by one, so order was built in. Transformers read everything in parallel, so order must be added on purpose.

03Sinusoidal positional encoding

The original paper used fixed sine and cosine waves of different speeds. For position pos and dimension pair i:

PE(pos, 2i) = sin(pos / 100002i/d)  ·  PE(pos, 2i+1) = cos(pos / 100002i/d)

Early dimensions change quickly from one position to the next (fast waves). Later dimensions change slowly (slow waves). Together, every position gets a unique pattern, like a fingerprint.

🕰️

Like the hands of a clock. The seconds hand moves fast, the minutes hand slower, the hours hand slowest. Reading all three together tells you the exact time. Fast and slow waves together tell the model the exact position.

Demo · Positional encoding for each position (first 8 of 512 dimensions)
positional_encoding.py
import numpy as np

def positional_encoding(n_positions, d_model):
    pe = np.zeros((n_positions, d_model))
    pos = np.arange(n_positions)[:, None]
    div = np.power(10000, np.arange(0, d_model, 2) / d_model)
    pe[:, 0::2] = np.sin(pos / div)      # even dimensions
    pe[:, 1::2] = np.cos(pos / div)      # odd dimensions
    return pe

pe = positional_encoding(50, 512)
print(pe.shape)
print(pe[1, :4].round(3))
(50, 512) [0.841 0.54 0.822 0.57 ]

04Learned positions, RoPE and ALiBi

Sinusoidal encoding is only one option. Here is what popular models use:

MethodHow it worksUsed inGood to know
Sinusoidalfixed sine/cosine waves added to embeddingsOriginal Transformerno extra parameters
Learned absolutea trainable vector for each position 0, 1, 2…BERT (512), GPT-2 (1,024)cannot go beyond the trained length
RoPE (rotary)rotates query and key vectors by an angle that depends on positionLLaMA, Mistral, Qwen, Gemmaencodes relative distance; can be stretched for longer context
ALiBiadds a penalty to attention scores that grows with distanceBLOOM, MPThandles longer inputs than seen in training
Why RoPE is popular: what matters most in language is often how far apart two words are, not their exact index. RoPE builds this relative distance directly into the attention scores, and tricks like RoPE scaling let models reach 128K-token contexts.

05Summary

  • The transformer has an encoder (understand) and a decoder (write).
  • Attention by itself is order-blind, so positions must be added.
  • Sinusoidal encodings use fast and slow waves to give each position a unique pattern.
  • Modern LLMs mostly use RoPE, which encodes relative distance.
