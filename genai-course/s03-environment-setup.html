01Python refresher for AI

You do not need advanced Python for this course, but you must be comfortable with functions, lists and dictionaries, and simple classes. LLM APIs send and receive lists of dictionaries all the time, so this example uses a chat history:

refresher.py
# Functions: reusable blocks with inputs and a return value
def count_tokens(text: str, chars_per_token: float = 4.0) -> int:
    """Rough token estimate for English text."""
    return max(1, round(len(text) / chars_per_token))

# A small class: data (attributes) + behaviour (methods) together
class ChatHistory:
    def __init__(self, system_prompt: str):
        self.messages = [{"role": "system", "content": system_prompt}]

    def add(self, role: str, content: str) -> None:
        self.messages.append({"role": role, "content": content})

    def total_tokens(self) -> int:
        return sum(count_tokens(m["content"]) for m in self.messages)

    def __len__(self):
        return len(self.messages)

chat = ChatHistory("You are a helpful banking assistant.")
chat.add("user", "How do I reset my UPI PIN?")
chat.add("assistant", "Open your UPI app, choose the bank account and tap 'Reset UPI PIN'.")

print(len(chat), "messages")
print("approx tokens:", chat.total_tokens())
print([m["role"] for m in chat.messages])
3 messages approx tokens: 32 ['system', 'user', 'assistant']

02Virtual environments and pip

Different projects need different library versions. A virtual environment is a private folder of packages for one project, so projects do not break each other.

terminal
python -m venv .venv                 # create
source .venv/bin/activate            # activate (macOS/Linux)
.venv\Scripts\activate               # activate (Windows)

pip install openai streamlit python-dotenv
pip freeze > requirements.txt        # save exact versions
pip install -r requirements.txt      # recreate on another machine
deactivate
🍱

Like a separate tiffin box for each meal. Keep each project’s packages in its own box, so the dal from one does not spill into the rice of another.

Tip: add .venv/ to .gitignore. Share requirements.txt, not the environment folder.

05API keys, .env files and secrets hygiene

An API key is like your ATM PIN for an AI service: whoever has it can spend your money. Never put keys in your code. Put them in a .env file and load them at runtime:

.env
OPENAI_API_KEY=sk-demo-1234567890abcdef
APP_ENV=dev
load_env.py
# pip install python-dotenv
import os
from dotenv import load_dotenv

load_dotenv()                                  # reads .env from the current folder
key = os.getenv("OPENAI_API_KEY")
if not key:
    raise SystemExit("OPENAI_API_KEY is missing. Add it to your .env file.")

print("Environment:", os.getenv("APP_ENV", "prod"))
print("Key loaded:", key[:6] + "..." + key[-4:])   # never print the full key

Do ✅Don’t ❌
Keep keys in .env or a secrets managerPaste keys into notebooks you share
Add .env to .gitignore before the first commitCommit keys to GitHub, even to a private repo

Leaked a key? Revoke it in the provider dashboard immediately and create a new one. Deleting the commit is not enough: bots scan GitHub for keys within minutes.

07Summary

  • Know functions, lists of dicts and simple classes: LLM APIs use them everywhere.
  • One virtual environment per project; share requirements.txt.
  • Use Colab for a free GPU; save work to Drive or GitHub.
  • Git workflow: branch → add → commit → push → pull request.
  • Keys live in .env (ignored by Git) or a secrets manager, never in code.
  • Streamlit for apps and dashboards, Gradio for quick model demos.
