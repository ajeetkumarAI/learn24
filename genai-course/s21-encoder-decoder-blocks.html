Inside the Encoder and Decoder Blocks

⏱ 13 min read🎯 Intermediate🖼 3 diagrams🧪 2 live demos🐍 Python code

In Session 20 we saw the transformer from far away. Now let us open each block and look at every part inside it: what it does, why it is there, and how the same model behaves differently while training and while answering.

In this session

  • Encoder block: self-attention, feed-forward network, layer norm and residual connections
  • Decoder block: masked self-attention, cross-attention and the output head
  • Training (teacher forcing, all at once) vs inference (one token at a time)
  • A working encoder layer in PyTorch

01The encoder block

One encoder block has two sub-layers, each wrapped with a residual connection and layer normalisation:

Feed-forward network (FFN)

After attention mixes information between tokens, the FFN thinks about each token on its own. It is a small two-layer network: expand, apply an activation, shrink back.

FFN(x) = W₂ · GELU( W₁ · x + b₁ ) + b₂   (512 → 2048 → 512)
Part of one layer (d = 512)ParametersShare
Attention (W_Q, W_K, W_V, W_O)~1.05 million~1/3
Feed-forward (512 → 2048 → 512)~2.1 million~2/3

Surprise: most of a transformer’s parameters live in the FFNs, not in attention. Many researchers think the FFNs store a lot of the model’s factual knowledge.

Residual connections

Each sub-layer’s output is added back to its input: x + SubLayer(x). This gives gradients a direct path through deep networks, so even 100-layer models can be trained.

🛣️

Like a highway bypass. Traffic can go through the city (the sub-layer) or take the bypass straight ahead (the residual). Information never gets stuck in a jam.

Layer normalisation

LayerNorm rescales each token’s vector to mean 0 and spread 1 (then applies a learned scale and shift). This keeps numbers in a healthy range layer after layer. The original paper put it after the addition (Post-LN). Most modern LLMs put it before each sub-layer (Pre-LN), which trains more stably; many also use a lighter version called RMSNorm.

02The decoder block

The decoder block has three sub-layers:

  • Masked self-attention: the causal mask from Session 18 stops a token from seeing future tokens.
  • Cross-attention: queries come from the decoder, but keys and values come from the encoder’s output. This is how the decoder “reads” the source sentence.
  • Output head: a linear layer turns the final vector into one score per vocabulary word, and softmax turns scores into probabilities. Many models tie this layer’s weights to the input embedding table to save parameters.

03Training vs inference

The same model works in two very different ways depending on whether it is learning or answering.

TrainingInference
Decoder inputThe correct answer (shifted right)The model’s own previous outputs
SpeedAll positions in parallelOne forward pass per new token
DropoutOnOff (model.eval())
Memory trickNone neededKV cache of past keys and values
RiskNone from its own mistakesOne wrong token can lead the rest astray

04Code: an encoder layer in PyTorch

encoder_layer.py
import torch
import torch.nn as nn

layer = nn.TransformerEncoderLayer(d_model=512, nhead=8, dim_feedforward=2048,
                                   batch_first=True, norm_first=True)   # Pre-LN
encoder = nn.TransformerEncoder(layer, num_layers=6)

x = torch.randn(2, 10, 512)          # 2 sentences, 10 tokens, 512 numbers each
out = encoder(x)
print(out.shape)                     # same shape in, same shape out

params = sum(p.numel() for p in layer.parameters())
print(f"{params:,} parameters per layer")
torch.Size([2, 10, 512]) 3,152,384 parameters per layer

That is about 1.05 M for attention + 2.1 M for the FFN + a few thousand for the two LayerNorms, matching the table above.

05Summary

  • Encoder block = self-attention + FFN, each with residual + LayerNorm.
  • The FFN holds about two-thirds of the parameters and works on each token separately.
  • Decoder block adds masked self-attention and cross-attention, then an output head over the vocabulary.
  • Training uses teacher forcing in parallel; inference generates one token at a time with a KV cache.
