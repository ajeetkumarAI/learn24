01Production architecture

02Indexing and incremental updates

Documents change every day. Re-embedding everything nightly is slow and costly. Instead, fingerprint each document and only process what changed:

incremental_index.py
import hashlib

def fingerprint(text):
    return hashlib.sha256(text.encode()).hexdigest()[:12]

index = {"fd_policy.pdf": fingerprint("FD penalty is 1%"),          # what is already indexed
         "kyc_rules.pdf": fingerprint("Aadhaar or passport"),
         "old_offer.pdf": fingerprint("Festive offer 2025")}

today = {"fd_policy.pdf": "FD penalty is 1%",                       # files in the source today
         "kyc_rules.pdf": "Aadhaar, passport or voter ID",
         "card_faq.pdf":  "Block your card from the app"}

to_add    = [f for f in today if f not in index]
to_update = [f for f in today if f in index and fingerprint(today[f]) != index[f]]
to_delete = [f for f in index if f not in today]
print("add:", to_add, "| update:", to_update, "| delete:", to_delete, "| skip:", len(today) - len(to_add) - len(to_update))
add: ['card_faq.pdf'] | update: ['kyc_rules.pdf'] | delete: ['old_offer.pdf'] | skip: 1
  • Add new files, re-embed changed ones, delete chunks of removed files (very important: old policies must not keep answering!).
  • LangChain’s indexing API (RecordManager + index()) does this bookkeeping for you.
  • Keep an effective_date in metadata so you can prefer the latest version.

04Hallucinations and mandatory citations

  • Instruct the model to answer only from the context and to say “I don’t know” otherwise.
  • Make citations mandatory: every claim must point to a chunk id or page.
  • Automatically verify citations: does the cited chunk exist and contain the claim? If not, regenerate or refuse.
  • If retrieval finds nothing relevant, refuse politely and suggest who to contact.

  • Send fewer, better chunks (re-ranking and compression pay for themselves).
  • Route easy questions to a small model; keep the large model for hard ones.
  • Cache frequent questions.
  • Batch embedding jobs and only re-embed changed documents.

07Summary

  • Use incremental indexing: add, update and delete only what changed.
  • Budget latency per stage; stream answers and cache frequent questions.
  • Make citations mandatory and verify them; refuse when nothing is found.
  • Cut cost with fewer chunks, smaller models and caching.
  • Enforce access control at retrieval, mask PII, and keep audit logs.
