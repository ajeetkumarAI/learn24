An LLM knows a lot about the world, but nothing about your company’s documents, and its knowledge stops at a training date. Retrieval-Augmented Generation (RAG) fixes this: first find the right information, then let the model answer from it. It is the most common GenAI pattern in companies today.

In this session

  • The two halves of RAG: indexing (offline) and answering (online)
  • Why RAG matters in production: fresh data, private data, citations, access control
  • RAG vs fine-tuning vs long-context prompting, with a decision helper
  • The NovaBank policy assistant we build through this module
  • A complete minimal RAG in LangChain

01The RAG workflow

RAG has two halves. The indexing half runs ahead of time; the answering half runs every time a user asks something.

📚

Like an open-book exam. The student (LLM) is smart, but instead of answering from memory, they first open the right page of the textbook (retrieval) and then write the answer from it (generation).

02Why RAG is critical in production

Problem with a plain LLMHow RAG helps
Does not know private data (policies, tickets, contracts)retrieves from your own documents
Knowledge has a cut-off datere-index new documents any time, no retraining
Hallucinates confident answersanswers are grounded in retrieved text
No proof for the answerevery answer can cite its source page
Everyone sees everythingfilter documents by the user’s access rights at retrieval time
Fine-tuning is costly for changing factsupdating an index is cheap and fast

04Reference architecture: NovaBank policy assistant

Through this module we build one realistic project: an internal assistant that answers employee questions from NovaBank’s policy documents, with citations and access control.

05A complete minimal RAG in LangChain

About 20 lines from PDF to cited answer. Later sessions improve each step.

minimal_rag.py
# pip install langchain-community langchain-openai langchain-chroma pypdf
from langchain_community.document_loaders import PyPDFLoader
from langchain_text_splitters import RecursiveCharacterTextSplitter
from langchain_openai import OpenAIEmbeddings, ChatOpenAI
from langchain_chroma import Chroma
from langchain_core.prompts import ChatPromptTemplate

docs = PyPDFLoader("fd_policy.pdf").load()                                   # 1. load
chunks = RecursiveCharacterTextSplitter(chunk_size=800, chunk_overlap=100).split_documents(docs)   # 2. chunk
db = Chroma.from_documents(chunks, OpenAIEmbeddings(model="text-embedding-3-small"))              # 3-4. embed + store
retriever = db.as_retriever(search_kwargs={"k": 4})

prompt = ChatPromptTemplate.from_template(
    "Answer only from the context. Cite page numbers like [p.4]. "
    "If the answer is not in the context, say you don't know.\n\nContext:\n{context}\n\nQuestion: {question}")
llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)

question = "What is the penalty for breaking an FD early?"
found = retriever.invoke(question)                                            # retrieve
context = "\n\n".join(f"[p.{d.metadata['page'] + 1}] {d.page_content}" for d in found)
print(llm.invoke(prompt.format(context=context, question=question)).content)  # augment + generate
Breaking an FD early reduces the interest rate by 1% [p.4]. (sample output)

06Summary

  • RAG = retrieve the right chunks, then generate an answer from them.
  • Indexing runs offline; answering runs per question.
  • RAG gives fresh, private, cited answers with access control.
  • Fine-tune for behaviour; use RAG for knowledge; use long context for one-off documents.
