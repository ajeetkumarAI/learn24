Advanced Attention

⏱ 14 min read🎯 Intermediate🖼 4 diagrams🧪 2 live demos🐍 Python code

Attention is powerful, but it has a price: every token looks at every other token. Double the text, and the work becomes four times bigger. In this session, let us see how real models handle this, look at attention on real sentences, and understand what goes wrong when the context becomes very long.

01The n² problem

For n tokens, attention builds an n × n table of scores, in every head of every layer. So the work grows with n²:

Demo · Context length calculatorExample: Llama 3.1 8B (32 layers, 8 KV heads × 128, FP16)
Full score table = n × n × 2 bytes, per head, per layer, if stored. KV cache = 128 KB per token for this model.
🤝

Like everyone at a function shaking hands with everyone else. With 10 guests it’s quick. With 1,000 guests, it takes forever, because the number of handshakes grows much faster than the number of guests.

02Efficient attention variants

Researchers have found many ways to make attention cheaper. Some approximate it (look at fewer pairs), and some compute it exactly but smarter.

TechniqueIdea in one lineExact?Used in
Sliding-window (local)Each token looks only at the last W tokensNo, approximateLongformer, Mistral 7B (window 4,096)
Sparse + global tokensLocal window plus a few tokens that see everythingNo, approximateLongformer, BigBird
Linear / low-rankApproximate the n × n table with smaller matricesNo, approximateLinformer, Performer
FlashAttentionCompute attention in small tiles inside fast GPU memory, never storing the full tableYesMost modern training and serving stacks
Multi-query (MQA)All heads share one set of keys and valuesYes (different architecture)PaLM, Falcon
Grouped-query (GQA)Groups of query heads share keys and valuesYes (different architecture)Llama 2 70B, Llama 3, Mistral

MHA vs GQA vs MQA

During generation, the model stores the keys and values of all previous tokens (the KV cache). With many heads, this cache becomes huge. GQA and MQA let several query heads share the same keys and values:

FlashAttention is the big win in practice. It gives the same answer as normal attention but avoids writing the n × n table to slow GPU memory, so it is much faster and uses memory that grows only linearly with length. In PyTorch, torch.nn.functional.scaled_dot_product_attention uses such fused kernels automatically when available.

03Attention on real sentences

Change one word at the end of the sentence and see how the attention of “it” moves:

Demo · Attention heatmap

You can see real attention weights from any Hugging Face model by asking for them:

see_attention.py
from transformers import AutoTokenizer, AutoModel

tok = AutoTokenizer.from_pretrained("bert-base-uncased")
model = AutoModel.from_pretrained("bert-base-uncased", output_attentions=True)

inputs = tok("The animal didn't cross the street because it was too tired", return_tensors="pt")
out = model(**inputs)

print(len(out.attentions))        # one entry per layer
print(out.attentions[0].shape)    # (batch, heads, tokens, tokens)
12 torch.Size([1, 12, 15, 15])

For a visual, interactive view of every head, try the open-source BertViz library (pip install bertviz) in a notebook.

Careful when reading attention maps. High attention does not always mean “this word caused the answer”. Attention is one useful window into the model, not a full explanation.

04What breaks as context grows

Modern models advertise 128K or even 1M-token windows. That does not mean they use every token equally well. Here is what goes wrong:

  • Memory and cost: the KV cache grows with every token. In our calculator, 128K tokens need about 16 GB just for the cache of an 8B model, more than the model weights themselves.
  • Lost in the middle: models find facts at the start and end of a long prompt more reliably than facts buried in the middle.
  • Attention gets spread thin: with thousands of tokens competing, important ones can get a small share of attention.
  • Position limits: a model trained on 8K-token texts may behave badly at 32K unless its positional encoding is stretched (methods like RoPE scaling and YaRN).

Practical tips for long prompts

  • Put the instructions and the most important facts at the start or the end.
  • Prefer RAG: retrieve the 5 most relevant chunks instead of pasting 300 pages.
  • Summarise old conversation turns instead of keeping every message.
  • Test with “needle in a haystack” style checks on your own documents before trusting a long-context model.

05Summary

  • Attention cost grows with n²; the KV cache grows with n.
  • Sliding-window and sparse attention skip pairs; FlashAttention stays exact but computes smarter.
  • GQA / MQA share keys and values across heads to shrink the KV cache.
  • Attention maps are a useful view, but not a full explanation.
  • Long context brings memory cost, lost-in-the-middle and position limits, so design prompts and RAG with care.
