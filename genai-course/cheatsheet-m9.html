Module 9 cheat sheet: LangChain + RAG + LangGraph

RAG answers from your own documents: extract and chunk them well, retrieve the best chunks, generate with citations, and measure everything.

The RAG pipeline

Offline: load → extract → chunk → embed → store
Per question: embed query → retrieve → re-rank → prompt → answer + citations
  • Fine-tune for behaviour; RAG for knowledge; long context for one-off documents. S31 →
  • Extraction quality decides RAG quality; keep tables as Markdown. S32 →
  • Start with 300–800 token chunks plus overlap; recursive splitting is the safe default. S33 →
  • Use the same embedding model for documents and queries. S34 →

LangGraph and production

  • LangGraph = state + nodes (steps) + edges (arrows), with conditional edges and cycles. S37 →
  • Agentic RAG: grade the retrieved chunks, rewrite the query and retry, then check the answer. S37 →
  • Index incrementally: add, update and delete only what changed. S38 →
  • Make citations mandatory; refuse when nothing relevant is found. S38 →
  • Apply access control at retrieval, mask PII, keep audit logs. S38 →

Code: Reciprocal Rank Fusion (no libraries)

def rrf(rankings, k=60):
    scores = {}
    for ranking in rankings:
        for rank, doc in enumerate(ranking, start=1):
            scores[doc] = scores.get(doc, 0) + 1 / (k + rank)
    return sorted(scores.items(), key=lambda x: -x[1])

bm25  = ["FD_rules_p4", "Savings_p2", "FD_faq_p1"]    # keyword ranking
dense = ["FD_faq_p1", "FD_rules_p4", "Loan_p9"]       # vector ranking
print(rrf([bm25, dense]))     # FD_rules_p4 and FD_faq_p1 come out on top

Common mistakes

  • Different embedding models for documents and queries.
  • Chunks with no metadata: no filters, no citations, no access control.
  • Checking permissions after generation instead of at retrieval.
  • Shipping without a golden test set, so you cannot tell if a change helped.
  • Stuffing 20 chunks into the prompt: higher cost, and the answer often gets worse.
